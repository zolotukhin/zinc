# ZINC v0.1.0 release preparation

The first binary release is undergoing qualification. This file records its scope; the public release body is generated from the approved candidate's `validation.json` by `tools/release.py finalize`. Do not publish a hand-filled hardware table or copy results from source builds.

## Distribution scope

- `zinc-v0.1.0-linux-x86_64-vulkan.tar.gz`: R9700 (RDNA4) and Intel Arc Pro B70 / Xe2; glibc 2.35+ and a compatible Vulkan 1.3 driver.
- `zinc-v0.1.0-linux-x86_64-rocm.tar.gz`: R9700 (`gfx1201`), glibc 2.39+, ROCm 7.2.4; Ubuntu 24.04 is the reference userspace.

Metal remains an unsigned preview outside these stable archives. Additional
Mac GPU families, RDNA3 and Strix Halo can be qualified separately later.

CUDA remains experimental and source-only. Intel Macs, Linux ARM64, musl and native Windows have no 0.1.0 archive. Models and GPU drivers are installed separately. Read [binary installation](https://zolotukhin.ai/zinc/docs/binary-releases/) for requirements, backend selection, verification, upgrades and rollback.

## Evidence and supported behavior

The candidate must include all three selected Linux GPU profiles and each profile's exact model hashes/context limits. It tests packaged assets, diagnostics, reference tokenization/continuations, HTTP health/models/raw/chat streaming, cancellation/recovery and context boundaries. Vulkan additionally runs 376 numerical shader reference cases; ROCm runs 305 partial-tile cases against the kernel source embedded in the executable. The report identifies the actual GPU/OS/driver and binds all results to the final archive digest/full source SHA.

Qualification uses greedy decoding, one slot and each backend's default KV/MTP settings. The pinned native reference uses F32 K/V. It does not establish performance claims or certify every context/KV/MTP/concurrency path. Vulkan includes browser chat; ROCm's standalone server has CLI/HTTP chat without the browser UI or hot model switching. Publish only the feature/model combinations demonstrated in that candidate.

The small Qwen3 0.6B starter has [reviewed Vulkan inference coverage](../STARTER_QUALIFICATION.md)
at 2,048 context tokens on R9700 and Intel. It is not recommended for chat,
thinking or coding. Its three recorded coding tasks fail on both ZINC and the
separate native control. Qwen3.5 9B is the starting chat model on either Linux
backend. The promoted catalog still requires a fresh final-version candidate.

## Included corrections and known limits

Gemma's Vulkan path now respects the sliding window and per-layer KV sizes.
ROCm Gemma MoE batched prefill is enabled by default after partial-tile and
router-precision corrections; the serial path remains available for diagnosis.
Vulkan uploads reuse at most 64 MiB of staging memory, and pipeline loading
selects kernels for the loaded model. Each change retains its regression tests
and exact-byte preview evidence in the linked engineering reports.

The [Intel performance diagnostic](../INTEL_PERFORMANCE.md) shows slower decode
than llama.cpp on all seven models and mixed prefill results on its recorded
earlier archive. Loading-time and temporary-memory improvements do not establish
an inference-throughput win. The [R9700 ROCm Gemma measurements](../ROCM_GEMMA_MOE_PREFILL.md)
show gains for that model and configuration only. These diagnostics are separate
from candidate certification; 0.1.0 must not claim universal performance parity.

## Publication

The generated candidate includes archive checksums, per-file metadata, exact model policy, validation results, installer, release notes and offline provenance. After review, the protected publisher creates the final tag and publishes those same bytes. It verifies public downloads and installation in dependent jobs.

The Intel SSH worker and R9700 native worker have qualified one common
`0.1.0-rc.1` candidate in [run 41705323449](https://github.com/zolotukhin/zinc/actions/runs/41705323449).
All three mandatory profiles pass on the exact archives; the
[unchanged candidate report](/zinc/validation/release-candidate-0.1.0-rc.1-2026-11-03.json)
records all model, numerical, native-reference, API and cleanup evidence.
Rehearse protected publication and public installation as described in
[release engineering](https://zolotukhin.ai/zinc/docs/releasing/). Build and
qualify a separate final `0.1.0` candidate before stable publication; RC bytes
cannot be renamed. Apple credentials are outside this launch's requirements.

process are verified.
