# ZINC v0.1.0 release preparation

The first binary release is undergoing qualification. This file records its scope; the public release body is generated from the approved candidate's `validation.json` by `tools/release.py finalize`. Do not publish a hand-filled hardware table or copy results from source builds.

## Distribution scope

- `zinc-v0.1.0-macos-aarch64-metal.tar.gz`: Apple Silicon, macOS 15+ and each chip's factory OS minimum. Developer ID signing/notarization is required.
- `zinc-v0.1.0-linux-x86_64-vulkan.tar.gz`: AMD RDNA3/RDNA4, Strix Halo (RDNA 3.5), Intel Arc Xe2; glibc 2.35+ and a compatible Vulkan 1.3 driver.
- `zinc-v0.1.0-linux-x86_64-rocm.tar.gz`: AMD `gfx1201`, glibc 2.39+, ROCm 7.2.4; Ubuntu 24.04 is the reference userspace.

CUDA remains experimental and source-only. Intel Macs, Linux ARM64, musl and native Windows have no 0.1.0 archive. Models and GPU drivers are installed separately. Read [binary installation](/zinc/docs/binary-releases/) for requirements, backend selection, verification, upgrades and rollback.

## Evidence and supported behavior

The candidate must include all nine required GPU profiles and each profile's exact model hashes/context limits. It tests packaged assets, diagnostics, reference tokenization/continuations, HTTP health/models/raw/chat streaming, cancellation/recovery and context boundaries. Vulkan additionally runs the 84-case numerical shader reference suite. The report identifies the actual GPU/OS/driver and binds all results to the final archive digest/full source SHA.

Qualification uses greedy decoding, one slot, f32 KV and each backend's default MTP setting. It does not establish performance claims or certify every context/KV/MTP/concurrency path. Metal/Vulkan include browser chat; ROCm's standalone server has CLI/HTTP chat without the browser UI or hot model switching. Publish only the feature/model combinations demonstrated in that candidate.

The small Qwen3 0.6B starter is initially experimental for Metal/Vulkan qualification. ROCm starts with its supported Qwen3.5 9B path. The starter must be reviewed/promoted in the catalog before stable publication, followed by a new final-version candidate.

## Publication

The generated candidate includes archive checksums, per-file metadata, exact model policy, validation results, installer, release notes and offline provenance. After review, the protected publisher creates the final tag and publishes those same bytes. It verifies public downloads and installation in dependent jobs.

Provision workers, Apple credentials and the protected environment; review the first real hardware matrix and rehearse publication as described in [release engineering](/zinc/docs/releasing/). Issue #10 stays open until the public binaries and automatic release process are verified.
