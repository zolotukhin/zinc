# ZINC 0.1.0 release readiness

The latest qualification work fixes Intel router reductions, Gemma's Vulkan
sliding-window attention, dense-prefill precision, per-layer KV allocation and
prefill cancellation. The stronger long-prefix gate exposed a ROCm Gemma MoE
disagreement. Correcting partial quantization tiles and router precision
restores its batched prefill by default, with numerical and complete native
continuation tests. Vulkan model uploads now use a bounded staging buffer,
and model-specific pipeline loading avoids compiling unused kernels.
[Intel OpenCode validation](../INTEL_OPENCODE_VALIDATION.md) keeps actual-client
outcomes separate from inference correctness. The latest seven-model Intel
archive passes 203/203 API checks. Both Gemmas and all four larger Qwens pass
all 18 coding tasks; the starter completes 0/3 on both ZINC and a separate pinned
native control. Earlier failures retain their exact source and launch context.
These are source-specific diagnostics. Final candidate qualification remains
pending.

The [reference audit](../RDNA4_REFERENCE_VALIDATION.md) corrects the earlier HIP
revision claim: its recorded executable reports an older revision than the
intended checkout. Historical results retain their exact reference hashes and
diagnostic scope. Fresh worker runs must verify native reference backends and
unchanged executable/library identities, alongside the current cancellation
and EOS checks.

Target: `v0.1.0`. Tracking: [issue #10](https://github.com/zolotukhin/zinc/issues/10).
Release automation landed in [PR #33](https://github.com/zolotukhin/zinc/pull/33).

The approved launch scope is Linux first: Vulkan on R9700 and Intel Xe2, and
ROCm on R9700. Metal remains an unsigned preview. Apple signing and additional
Mac/AMD hardware do not block this release. The policy retains the wider
preview registry while `release` selects the two archives and three mandatory
hardware profiles for candidate certification and publication.

## Distribution contract

The [release policy](https://github.com/zolotukhin/zinc/blob/main/config/release/targets.json)
is the source of truth for targets, OS/ABI floors, hardware profiles, model
hashes, context limits, and the reference engine revision.

| Archive suffix        | Runtime baseline                                     | Qualification scope               |
| --------------------- | ---------------------------------------------------- | --------------------------------- |
| `macos-aarch64-metal` | Unsigned preview; macOS 15+, native ARM64            | Optional Apple7–Apple10 readiness |
| `linux-x86_64-vulkan` | glibc 2.35+, Vulkan 1.3 driver                       | RDNA4 and Intel Xe2               |
| `linux-x86_64-rocm`   | glibc 2.39+, ROCm 7.2.4 and runtime compiler headers | RDNA4 `gfx1201`                   |

Metal and Vulkan include browser chat. ROCm provides CLI/HTTP chat without the
built-in UI or hot model switching. CUDA remains experimental and source-only.
Models and GPU drivers are separate installations.

Every selected release profile is mandatory; an omitted or skipped profile
cannot count as a pass. The Linux-first scope is an explicit policy choice.
Historical source-build benchmarks and OpenCode trials remain useful evidence,
but cannot certify a different packaged executable.

## Implemented

- Frozen source SHA/version and baseline CPU/OS targets for all three archives.
- Complete shader inventories, dependency/ABI audits, normalized archive metadata,
  per-file checksums, and executable identity probes.
- Verified user-local installation, atomic activation, backend selection, safe
  reinstall, failure handling, and rollback without moving models.
- Separate untrusted packaging, trusted candidate, signing, hardware validation,
  provenance, protected promotion, and public-install workflows.
- Packaged-byte GPU/model/API/reference checks, process cleanup, generated
  validation tables, and resumable publication that refuses replacement bytes.

See [release engineering](https://zolotukhin.ai/zinc/docs/releasing/) for the
maintained commands and configuration, and [binary installation](https://zolotukhin.ai/zinc/docs/binary-releases/)
for the user-facing contract. This readiness note replaces the original design
proposal; implementation details belong in those guides and the policy.

## Remaining launch gates

1. Approve protected publication of the certified RC, then verify its public
   downloads and clean installation. The common-source hardware matrix is
   complete; preview readiness reports are not substitutes for it.
2. Build and qualify a separately embedded final `0.1.0` candidate. Preserve
   the reviewed starter's Vulkan/profile/context scope and disabled
   chat/thinking recommendations in that candidate. Keep optional
   KV/MTP/context/concurrency claims within their tested scope; review
   performance regressions separately.
3. Rehearse failed validation, unavailable workers, interrupted upload, duplicate
   versions, and rollback. CPU contracts cover these failure paths, including an
   accepted upload whose reply is lost and a subsequent write-free retry. The
   actual Linux RC publication/public-install rehearsal remains pending. Any
   fixes needed during rehearsal require a new final-version candidate.
4. Publish the approved candidate unchanged. Verify public downloads and clean
   installation before closing issue #10.

No release tag or public archive should be created from the packaging preview.
