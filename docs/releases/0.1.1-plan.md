# ZINC 0.1.1 candidate

Prepare a Linux maintenance candidate from one frozen main commit, incorporating
the corrections and usability improvements since 0.1.0. The candidate embeds
`0.1.1`; publication can promote its exact tested bytes after review. The
published 0.1.0 archives remain the current stable download during preparation.

## Scope

- Linux x86_64 Vulkan: AMD Radeon AI PRO R9700 and Intel Xe2.
- Linux x86_64 ROCm: R9700 with the existing ROCm 7.2.4 runtime contract.
- Retain the current seven Vulkan model pins and six ROCm model pins, each at
  its release-policy context and default generation settings.
- Include the [reviewed changes](0.1.1-changes.md). Existing CLI commands remain
  available; the new serving/discovery interfaces are additive.
- Metal remains an unsigned preview; native Intel, CUDA, additional GPU families,
  and wider context/concurrency claims need separate qualification.

## Required evidence

1. Run host, release failure-path, privacy, formatting, site, and package checks.
2. Build the final-version Vulkan and ROCm archives once in the pinned build
   environments; verify ABI/dependencies and clean installation outside a checkout.
3. Qualify those exact archives on `vulkan-rdna4`, `rocm-rdna4`, and
   `vulkan-intel-xe2`: model hashes, native tokenizer/continuation agreement,
   numerical GPU cases, Gemma sliding windows, HTTP/SSE, context boundaries,
   cancellation, recovery, and process cleanup.
4. Exercise the new installed CLI and agent discovery contracts. Run actual
   OpenCode/OpenClaw acceptance checks against candidate bytes where supported,
   retaining starter limitations and failed attempts.
5. Rehearse 0.1.0-to-candidate upgrade, rollback, reinstall, executable links, and
   model-cache preservation in an isolated prefix.
6. Inspect archive identities, all three hardware reports, generated release
   notes, checksums, and offline provenance before proposing publication.

The release workflow and private workers own GPU reservations and stop their
processes. An unavailable Intel endpoint leaves that profile pending or failed;
AMD evidence cannot replace it. No incomplete run is certified as stable.

## Progress

Preparation in progress. Candidate run, frozen source, archive hashes, and actual
results will be recorded after the workflow produces them. Historical reports
are retained as context, not substituted for this candidate's results.
